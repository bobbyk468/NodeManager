# Phase 1 Rubric-Anchored Pilot — Scoped Proposal (Not Implemented)

**Status**: proposal only. Nothing in this document has been built. This
exists to scope the work and get sign-off on the stop gate *before* any
of it is implemented, per `docs/CONCEPTGRADE_RECOVERY_PLAN_2026-08-19.md`'s
phased plan and the explicit instruction that adopting that plan as a
roadmap is not the same as committing to implement it immediately.

> ⚠️ **Feasibility only, not confirmatory (revised 2026-08-19, second
> review round)**: at 5-10 question families this pilot is a feasibility
> check on whether the rubric-anchored approach is worth scaling to a
> real confirmatory study — it is explicitly **underpowered for a
> confirmatory claim** and its result must not be reported or cited as
> "rubric graphs improve grading accuracy," only as "the stop gate was/
> wasn't met in a small pilot, justifying/not justifying a larger,
> adequately-powered follow-up." This distinction was previously
> implicit; it is now the pilot's stated framing throughout this
> document, per explicit second-review feedback that a 5-10-family pilot
> must not be allowed to accumulate the same evidentiary weight the
> Mohler-based exploratory work incorrectly accumulated in Findings 4-6.

**Prerequisite**: Phase 0 integrity work (REPRODUCIBILITY.md Finding 6)
should be complete and merged before this starts — a pilot built on top
of unfixed cache-staleness or reference-answer-propagation bugs would
just reproduce the same class of problem in new code.

## 1. Why this pilot, not a bigger commitment

The recovery plan's full "Rubric-Anchored Claim Trace" redesign — new
question specifications, a deterministic proposition-level scorer,
three-blinded-grader human labels, a frozen external test set — is a
multi-week-to-month undertaking. Before committing to that scale, this
pilot answers the one question that determines whether it's worth doing
at all: **does giving an LLM a question-specific rubric (not a global
KG) produce a measurable, held-out improvement over the same LLM with no
rubric at all?** If not, no amount of graph machinery built on top of a
rubric will help either, and the honest reframing is "ConceptGrade's
value is in diagnostics/feedback, not point-score accuracy" (Phase 4 of
the recovery plan).

## 2. Scope

- **5-10 question families**, deliberately *not* drawn from the Mohler
  set already used for Findings 4-6's prompt/architecture selection (see
  REPRODUCIBILITY.md's Mohler freeze note). Candidate sources: a held-out
  slice of DigiKlausur or Kaggle ASAG not yet touched by this
  investigation, or a small newly-collected set if neither has enough
  untouched, labelable material.
- **Expert-authored rubric propositions** for each question family:
  atomic gradable claims, point weight, required/optional status,
  acceptable alternative phrasings, known misconceptions specific to
  that question. Authored by a domain expert, not generated by the KG or
  an LLM (the KG may inform authoring, per the recovery plan's "library,
  not rubric" framing, but the propositions themselves need a human
  author to avoid reproducing Finding 3's tautology problem one level up).
- **Criterion-level human labels**: for a stratified subset of student
  answers, **at least two independent human annotators** label which
  propositions were satisfied, contradicted, or not addressed — not just
  an overall score — with **disagreements resolved by adjudication**
  (a third annotator or a discussion-to-consensus pass, decided and
  documented before labeling starts, not improvised afterward). A single
  annotator's labels cannot distinguish "the LLM is wrong" from "the
  annotator's judgment call was idiosyncratic," which is exactly the
  single-source-of-truth problem this project's own prior work
  (REPRODUCIBILITY.md's retracted reliability-ceiling analysis) ran into.
  Inter-annotator agreement (e.g. Cohen's/Fleiss' kappa per criterion
  type) is reported alongside the diagnostic-validity numbers, not
  omitted. This is what lets the pilot check diagnostic validity (does
  the LLM's proposition-level judgment agree with an adjudicated human
  label?), not just aggregate MAE.

## 3. Four arms compared — arms 2-4 information-equal and compute-matched; arm 1 deliberately information-poorer by design

Per the recovery plan's explicit warning: comparing the new system only
against a weaker prompt would measure an information/compute advantage,
not an architectural one — **among arms that are supposed to be
information-equivalent**. **Revised 2026-08-19 (second and third review
rounds)**: the no-rubric direct baseline is now a real fourth arm run
under the same protocol as the other three, not an "already-available"
external reference point computed differently. Two clarifications on
scope, corrected 2026-08-19 (third review round) after "equal
information across all four arms" was flagged as self-contradictory —
arm 1 exists specifically *to measure* the value of having rubric
information at all, so it cannot be both deprived of that information
and held information-equal to the arms that have it:

- **Equal information, enforced, not assumed — applies to arms 2, 3, and
  4 only.** Every fact the graph arm's (arm 4's) edges encode (e.g.
  "concept X is a prerequisite for concept Y") must also be handed to
  arms 2 and 3 as plain text in their prompt — as a flat, unstructured
  list of the same facts, not omitted and not summarized away. If arm 4
  knows something arms 2/3 don't, any measured difference between them
  could be an information advantage, not a structural one. This is
  checked mechanically before running the pilot: every edge in the
  rubric graph must have a corresponding sentence in the flat-fact list
  given to arms 2 and 3. **Arm 1 is deliberately excluded from this
  constraint** — it has no rubric propositions and no rubric-derived
  facts at all, by design, because arm-1-vs-the-rest is exactly the
  comparison that measures whether having rubric information helps in
  the first place. Enforcing information-equality on arm 1 would erase
  the one comparison this pilot most needs.
- **Matched compute, measured not assumed, reported for all four arms**:
  LLM calls and total input+output tokens per graded answer are logged
  for every arm (including arm 1, whose lower token count is expected
  and informative, not a defect to fix) and reported as a table
  alongside the accuracy results. Among arms 2-4 specifically, if one
  systematically uses substantially more calls or tokens (e.g. the
  proposition scorer making one call per proposition vs. one holistic
  call), that's reported explicitly as a confound, and where feasible a
  compute-matched variant (e.g. batching proposition judgments into one
  call) is run and compared alongside the unmatched version — the pilot
  does not let an accuracy gain among the equal-information arms quietly
  ride on an unreported compute advantage.

1. **No-rubric direct baseline**: question + reference answer + student
   answer only, one holistic LLM call, no rubric propositions of any
   kind. This is the "does having ANY rubric help at all" control — its
   absence as a run-under-the-same-protocol arm was the specific gap
   flagged in the second review.
2. **Direct rubric LLM**: question + reference + rubric propositions
   (as text) + student answer, one holistic LLM call, no forced
   decomposition.
3. **Proposition scorer**: LLM independently judges each rubric
   proposition (supported / partially supported / contradicted / not
   addressed / abstain) against the student answer, deterministic
   point aggregation from those judgments — no graph, no additional
   structure beyond the flat proposition list.
4. **Rubric graph scorer**: identical propositions plus typed
   prerequisite/alternative/contradiction edges between them (and, per
   the equal-information rule above, the same edge facts also handed to
   arms 2-3 as flat text), same deterministic aggregation rule extended
   to use those edges.

Comparing arm 1 vs. the rest isolates whether having a rubric at all
helps. Comparing arm 3 vs. arm 4 isolates whether the *graph structure*
specifically adds value beyond flat proposition decomposition, now on a
genuinely equal information footing. Comparing arm 2 vs. arm 3 isolates
whether *decomposition itself* (forcing the LLM to judge criteria
separately rather than holistically) adds value.

## 4. Evaluation protocol

- **Split by question family**, not by student response — sibling or
  paraphrased questions must not cross the train/dev/test boundary.
- **Nested question-family cross-validation** for any development-time
  decision (prompt wording, aggregation rule details) — exactly the
  LOQO-style discipline already used elsewhere in this project, applied
  correctly this time at the family level, not just the individual-
  question level (see REPRODUCIBILITY.md Finding 6 on where the prior
  LOQO discipline fell short).
- **Freeze the test set before any prompt or architecture iteration** on
  it. No variant selection happens against the frozen test data — that
  was the single largest methodological problem in Findings 5/6's
  Mohler-based work, and this pilot exists partly to demonstrate the
  fix.
- **Primary outcome, chosen before running anything**: MAE (matching
  this project's existing convention) — or a pre-registered alternative
  (ordinal log loss, QWK) if the pilot's rubric-based scores turn out to
  be more naturally ordinal than continuous. Whichever is chosen, commit
  to it in this document (or an addendum) before results exist.
- **Secondary outcomes**: criterion-level precision/recall/F1 against
  the human proposition labels (this is the actual diagnostic-validity
  check — a system that gets the right total score for the wrong reasons
  is not what this pilot is trying to find), false-penalty rate on
  high-quality answers, cost/latency per graded answer.
- **Statistics**: question-family-clustered paired significance test as
  primary; response-level as secondary only, explicitly labeled as
  such given responses within a family aren't independent.

## 5. Stop gate

> Do not scale to the full redesign unless the rubric-graph scorer (arm
> 4) improves held-out MAE by **at least 5%** over the strongest of arms
> 1-3 (arm 1's no-rubric baseline is a legitimate comparator for this
> gate even though it isn't information-equal to arm 4 — beating it is
> necessary but not sufficient; beating the strongest of the
> information-equal arms 2/3 is what actually isolates the graph
> structure's contribution, see Section 3), **AND the
> question-family-clustered bootstrap (or
> permutation) 95% confidence interval for that improvement excludes
> zero** — a point estimate crossing 5% is not sufficient on its own.
> A point-estimate-only gate is exactly the kind of check the second
> review flagged as too permissive elsewhere in this project (see
> `verify_investigation_integrity.py`'s revised checks): at n=5-10
> question families a 5%-looking point estimate can easily arise from
> noise, so the gate is on the interval, not the point estimate. The
> improvement must also come without increasing the false-penalty rate
> on high-quality answers and without a drop in criterion-level
> diagnostic accuracy (adjudicated inter-annotator agreement as the
> reference) below a predeclared threshold.
>
> Given the feasibility-only framing in the header above, treat a met
> gate as "proceed to a properly powered confirmatory study," not as
> "the rubric-graph approach is validated" — the same distinction this
> project's Findings 4-6 correction established the hard way.

If the gate isn't met, the honest, defensible finding is that graph
structure over a rubric doesn't help either, on top of everything
Findings 4-6 already established about the KG-formula approach — and
the project's positioning moves to Phase 4 of the recovery plan
(diagnostics/feedback value, not point-score accuracy), which is itself
a legitimate, real contribution given how thoroughly the negative case
has been established by this point.

## 6. Estimated scope (order of magnitude, not a committed budget)

- Rubric authoring: several hours of expert time per question family,
  5-10 families.
- Human criterion-level labeling: a stratified subset (not every
  response) per family, likely 20-40 responses per family for adequate
  per-criterion precision/recall estimates, **labeled by at least two
  annotators each plus adjudication time** (revised 2026-08-19 — roughly
  doubles raw labeling time over a single-annotator pass, plus
  adjudication overhead for disagreements).
- LLM API cost: comparable order of magnitude to this session's Gemini/
  GPT/DeepSeek spend (~$10-20), assuming similar batching discipline —
  now across **four** arms instead of three, with per-arm token/call
  counts logged so any compute imbalance between arms is visible rather
  than assumed away.
- This is a multi-day pilot, not a same-session continuation — it should
  be scoped and resourced as its own piece of work, not squeezed into
  the tail of this investigation.

## 7. Explicitly not in this pilot's scope

Frozen *external* validation (recovery plan Phase 3), the full feedback/
human-review study (Phase 4), and any production deployment decision are
all downstream of this pilot's stop-gate outcome and are not being
scoped here. This document covers Phase 1 only.
